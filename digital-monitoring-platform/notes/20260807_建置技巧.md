## 1. 今日主題與概念摘要

### 一句話定位
建置層 = 「會搭」：Docker Compose 把六支柱拉起來、把模擬器/營運輸出餵進 Postgres 倉庫、用最佳實務讓儀表板與工作流可維護。**今天完成了第一條可驗證的 ELT 雛形管線。**

### 核心概念（2026-08-07 官方檢核）

1. **Airbyte 安裝已從 Docker Compose 轉向 abctl**：官方 GitHub discussion #40599（2024-07）宣告 Docker Compose 安裝棄用；現行 self-hosted 為 `abctl local install`（在 Docker Desktop/K8s 上建本地叢集，UI 在 :8000）。本次檢核版本：App 0.63.15 / Helm chart 0.422.2。支援 `--low-resource-mode`（低資源模式，本機學習適用）。**這代表六支柱 compose 檔不含 airbyte，它獨立用 abctl 起、與倉庫共用同一個 Postgres。**
2. **n8n 官方 Docker Compose 範本**：`docker.n8n.io/n8nio/n8n` 映像；docs 目前標示 stable=2.33.5 / beta=2.34.2。後台可用 SQLite（預設）或 **PostgreSQL（DB_TYPE=postgresdb + DB_POSTGRESDB_* 環境變數）** — 直接吃我們倉庫的 postgres，少一台 DB。官方 compose 另配 traefik 做 TLS（生產）；本機學習可省略。
3. **Superset 官方 compose 四種檔**：`docker-compose.yml`（互動開發，mount 前端原始碼）、`-light.yml`（輕量、多實例 NODE_PORT=9001/9002…）、`-non-dev.yml`（不可變映像）、`-image-tag.yml`（直接跑 release tag，如 `TAG=5.0.0`）。**官方明確警告：compose 非 production-ready**（metadata DB 在 docker volume 沒備份 = 資料風險）；且**官方不支援 Windows** — 建置層要跑 Superset 建議用 Linux VM/容器。
4. **ROS 模擬數據 = 現成的 ELT 練習資料**：`simulator/reports/baseline_*.json`（10 份、9 場景：chef_offline / delivery_surge / holiday_burst / lunch_peak(30/120) / multi_store / rolling_horizon_stress / set_meal_sync / station_failure / vip_insert），結構為 summary / sla(含 violation_details) / wait_times / stations.by_type / batch / peak_mode_triggered / total_events_logged。**正對應「raw 整包 JSONB 保留 → staging 型別化拆表 → marts 聚合」的分層練習。**
5. **本機 Docker 可用但 daemon 需手動啟動**：Docker 29.4.3 + Compose v5.1.3 已安裝；`com.docker.service` 停止中，從非管理員會話 `net start` 被拒（錯誤 5）。**驗證策略：用 PGlite（WASM PostgreSQL）跑同一份 SQL** — schema + 匯入 + 查詢全通過，證明 SQL 語法與管線邏輯正確；待 Docker 起來即可原樣對 Postgres 17 執行。
6. **ELT/倉庫最佳實務（本次落實）**：raw 層保留原始 payload（JSONB + GIN 索引）可回溯重處理；staging 層型別化 + 拆事實/明細表（正規化）；marts 層預聚合事實表 + 樞軸視圖（儀表板直接消費）；所有寫入冪等（ON CONFLICT），可重跑不髒資料。

## 2. 架構說明（已驗證的 ELT 雛形）

```
ROS 模擬器（simulator/reports/baseline_*.json — 本機真實 10 份）
   ↓ ① ros_import.py（EL：檔名解析場景 + JSON 原樣入庫）
┌────────────────────────────────────────────────┐
│ PostgreSQL 倉庫 restaurant_warehouse（3 層）      │
│  raw.ros_sim_report        JSONB 整包 + 檔名/場景/時間  10 列
│    ↓ ② 型別化拆表（T 的雛形；正式由 dbt 管）          │
│  staging.ros_sim_summary   每報告 1 列（度量）        10 列
│  staging.ros_sim_station_util 每報告×爐口 1 列        74 列
│  staging.ros_sim_sla_violation 每違規訂單 1 列        100 列
│    ↓ ③ 聚合                                            │
│  marts.fact_ros_scenario_metrics  每場景 1 列（重算）  10 列
│  marts.v_ros_station_util_pivot   爐口利用率樞軸視圖
│  marts.v_ros_sla_ranking          SLA 排名（最差在前）
└────────────────────────────────────────────────┘
   ↓ 消費層（下一步：Grafana table/stat 面板 + Superset 報表）
```

**驗證結果（PGlite = 真實 PostgreSQL 引擎，2026-08-07）**：
- schema 套用 ✅、200 條 INSERT ✅、JSONB containment 查詢（`payload @> '{"peak_mode_triggered": true}'`）✅
- 資料洞見：**SLA 達成率最差 = set_meal_sync 58.3% / delivery_surge 59.5%**（套餐同步與外送爆單是 SLA 殺手）；lunch_peak 30min 達成率最高 71.6% 但**完成率最差 61.4%**（尖峰短時段接單消化不完）— 這些就是未來儀表板的第一批 KPI。

## 3. 實用指令

```bash
# ── 平台起服務（骨架：postgres + grafana + n8n + superset）──
docker compose -f scripts/docker-compose.yml up -d
docker compose ps / logs -f n8n
docker compose down -v        # 連 volume 清掉重來

# ── Airbyte（官方現行方式，Compose 已棄用）──
winget install airbytehq.abctl   # 或官方安裝腳本
abctl local install --low-resource-mode
abctl local status               # UI: http://localhost:8000

# ── ROS 數據匯入倉庫（本機產物）──
python3 scripts/ros_import.py --reports "<ROS>/simulator/reports" --sql-only out.sql   # 只產 SQL
python3 scripts/ros_import.py --reports "<ROS>/simulator/reports"                      # 直接入庫

# ── 無 Docker 時的 SQL 驗證（PGlite WASM）──
npm i @electric-sql/pglite && node scripts/verify_pglite.mjs schema.sql import.sql

# ── 儀表板 KPI 查詢（Grafana/Superset 共用）──
SELECT * FROM marts.v_ros_sla_ranking;                       -- 哪場景最該改善
SELECT * FROM marts.v_ros_station_util_pivot;                -- 爐口瓶頸（oven/pack 0% = 該場景沒用到）
```

## 4. 與「餐廳營運監控」及「數位資料倉庫」的關聯

- 這條雛形管線就是藍圖的**第一段實作**：模擬器 = 外部資料源（之後換成真實 POS/ROS API），raw/staging/marts = 倉庫分層，Grafana/Superset = 消費層待接。
- KPI 已有：完成率、SLA 達成率、平均/最長等待、爐口利用率（OEE 概念）、批量節省 — 全部是餐廳營運儀表板的直接素材。
- 接下來的建置路徑很明確：Docker 起來 → 同份 SQL 灌 Postgres 17 → Grafana provisioning 一個「ROS 營運儀表板」→ Superset 接同庫做 SLA 深度報表。
