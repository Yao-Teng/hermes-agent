## 1. 今日主題與概念摘要

### 一句話定位
六支柱不是六套獨立工具，而是一條分工明確的整合管線；平台價值來自「**資料在管線中流動時的分層治理**」與「**告警後的閉環行動**」。

### 核心概念

1. **ELT 管線七元件**（dbt Labs 官方定義）：**Ingestion**（選源、拉取）→ **Loading**（落倉）→ **Transformation**（倉內清洗/建模/聚合）→ **Orchestration**（排程與依序執行）→ **Observability & Testing**（品質檢查/lineage/新鮮度）→ **Storage** → **Analysis**。ETL vs ELT 關鍵差異：T 在**載入之後、倉庫內**進行 — 資料可重處理、易迭代；dbt 是為 ELT 而生的工具。
2. **整合分工鐵律**：Airbyte 只做 **EL**（原封不動搬入 raw 層），dbt 只做 **T**（raw→staging→marts，測試+文件化），消費層只讀乾淨資料。不要在 Airbyte 裡做複雜轉換，也不要在 Grafana 裡做深層聚合。
3. **2026 生態大事：Fivetran + dbt Labs 合併完成**（2026-06-01 正式完成；2025-10-13 宣布）。合併公司 ARR 約 6 億美元、10,000+ 客戶、服務 100,000+ 資料團隊，口號「**Open Data Infrastructure for AI agents**」；CEO George Fraser、President Tristan Handy。首波聯合產品：
   - **dbt Core v2.0（alpha）**：Fusion engine 開源，**Apache-2.0**；dbt Core 承諾持續維護
   - **dbt State（preview）**：管線快取層，只 build 有變更的 model，號稱省 **30%+** 基礎設施成本
   - **dbt Wizard（beta）**：agentic 開發環境，自然語言輔助 model 撰寫/重構/除錯（grounded in lineage/tests/contracts）
   - **Agents Schema**：開源標準 — 在倉庫開單一 schema（如 `AGENTS`）以純 SQL 表存放 metrics 定義、語意模型、lineage、文件，作為 **AI agent 的共享 context 層**（任何倉庫/工具相容）
   - **AI Connector Builder**：AI 輔助從 API 文件快速生成 connector
   - 對我們的意義：dbt 路線圖更偏「AI 時代的可信資料基礎」，學習 dbt（model/ref/incremental/test/contract）方向不變且更受重視
4. **授權合規總表（2026-08 官方檢核，全站商用注意事項）**：
   | 工具 | 授權 | 商用關鍵 |
   |---|---|---|
   | PostgreSQL | PostgreSQL License（寬鬆） | 無限制 |
   | dbt Core | Apache-2.0（v2.0 Fusion engine 亦 Apache-2.0） | 無限制 |
   | Apache Superset | Apache-2.0 | 無限制 |
   | Grafana | **AGPL-3.0**（Grafana/Loki/Tempo 皆 AGPL） | 修改+對外提供服務需釋出修改；可另購商用授權 |
   | Airbyte | **ELv2**（2021-09-27 起、v0.30.0） | 3 大限制：不得當 managed service 賣、不得繞過 license key、不得移除授權標示；**內部商用 OK**；connectors/CDK 仍開源 |
   | n8n | **Sustainable Use License**（fair-code，n8n 自創詞） | 所有使用皆可，**除非**販售「價值完全/實質上來自 n8n 功能」的產品/服務；內部業務使用 OK |
5. **閉環接口：Grafana Webhook notifier**（docs release-13.1.3 檢核）：預設 JSON payload 結構 — `receiver` / `status`（firing|resolved）/ `orgId` / `alerts[]`（內含 `labels`、`annotations`、`values`（condition 數值）、`fingerprint`（去重用）、`startsAt`、`generatorURL`、`silenceURL`…）/ `groupLabels` / `commonLabels` / `externalURL` / `version` / `groupKey` / `state` / `title` / `message`。安全選項：**HMAC-SHA256 簽章**（header 預設 `X-Grafana-Alerting-Signature`，可加 timestamp header 防 replay，簽法 `HMAC(timestamp + ":" + body)`）；另有 custom payload template、Max Alerts、Disable resolved message。
6. **部署模型**：概念/建置期用 **Docker Compose 單機全棧**（postgres + airbyte + dbt + grafana + superset + n8n）；Airbyte 官方教學即以 Compose 起「Airbyte + 倉庫 + dbt + Airflow」現代資料棧；n8n 社群有 compose 自架 + Prometheus/Grafana 監控（單機/queue 模式）腳本。**Superset 建議 4GB+ RAM**，本機測試注意。

## 2. 架構 / 流程說明

### 六支柱整合藍圖（今日核心）
```
外部資料（POS/ROS/ERP/API）
   ↓ ① Airbyte（EL：550+ connectors、CDC 增量、原封不動）
┌────────────────────────────────────────┐
│ PostgreSQL 數位資料倉庫（單一真相源）     │
│  ├─ raw      原始層（Airbyte 寫入）      │
│  │    ↓ ② dbt（T：ref/source/test/doc） │
│  ├─ staging  清洗/型別/標準化            │
│  ├─ marts    星形模型/物化視圖           │
│  └─ metrics  TimescaleDB 時間序列        │
└──────────────┬─────────────────────────┘
      ┌────────┼───────────┐
 Grafana 秒級+告警│ Superset BI│ n8n 自動化
      │           │ 分析報表   │ 通知/開單/補救
      └─Webhook──┴─► n8n 閉環（HMAC 驗證）
```

### 告警閉環流程（Grafana → n8n）
```
[Alert Rule] 爐口利用率 > 90% for 5m
   ↓ firing
[Notification Policy] label 路由 → Contact point (Webhook)
   ↓ POST JSON（status / labels / values / fingerprint）
[n8n Webhook Trigger] 驗 HMAC 簽章 → 解析 payload
   ├─ IF status == firing → 嚴重度分支
   │    ├─ Slack/Telegram 通知值班
   │    ├─ 自動開單（寫 Postgres events 表）
   │    └─ AI Agent 分析 → HITL 審批 → 補救（重跑 dbt/通知店長）
   └─ status == resolved → 關單/通知解除
```

### 授權決策樹（商用情境）
```
內部使用（企業自用）→ 六支柱全免費自架 OK（Airbyte/n8n 皆允許內部商用）
對外提供服務：
  ├─ 賣「資料管線/ETL 服務」本身 → ⚠️ Airbyte ELv2 禁止（managed service 紅線）
  ├─ 賣「價值實質來自 n8n 功能」的產品 → ⚠️ 需 n8n 商用協議
  ├─ 修改 Grafana 並對外提供服務 → ⚠️ AGPL 需釋出修改（或購商用授權）
  └─ 其餘（賣自家應用/分析服務）→ 各工具皆可（但不可直接暴露 Airbyte UI/API）
```

## 3. 實用指令（部署模型 / 閉環設定）

### Docker Compose 全棧骨架（建置層預演）
```yaml
services:
  postgres:
    image: postgres:17            # 第零支柱：數位資料倉庫
    environment: [POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB]
    volumes: [pgdata:/var/lib/postgresql/data]
  airbyte:                        # EL（資源重，依官方 compose 起）
    image: airbyte/airbyte-bootloader   # 完整 compose 見 docs.airbyte.com
  dbt:                            # T：dbt build --target prod
    image: ghcr.io/dbt-labs/dbt-postgres:latest
  grafana:
    image: grafana/grafana        # 秒級監控+告警（port 3000）
  superset:
    image: apache/superset        # BI 分析（需 ≥4GB RAM）
  n8n:
    image: docker.n8n.io/n8nio/n8n # 閉環自動化（port 5678）
volumes: [pgdata]
```

### Grafana Webhook contact point → n8n（閉環設定）
1. Grafana：Alerts & IRM → Alerting → Contact points → + Add contact point → Integration=**Webhook**，URL=`http://n8n:5678/webhook/grafana-alert`
2. （選用）HMAC：設 Secret → Grafana 以 HMAC-SHA256 簽 body，送 `X-Grafana-Alerting-Signature` header
3. n8n：Webhook Trigger（POST）→ Code node 驗簽 → IF status 分支
```js
// n8n Code node：驗 Grafana HMAC 簽章（示意）
const crypto = require('crypto');
const sig = $input.first().json.headers['x-grafana-alerting-signature'];
const expected = crypto.createHmac('sha256', SECRET)
                       .update(rawBody).digest('hex'); // rawBody 須取原始 body
return [{ json: { ok: sig === expected, alert: $input.first().json.body } }];
```
4. payload 關鍵欄位：`alerts[0].status`（firing/resolved）、`alerts[0].labels.alertname`、`alerts[0].values`（condition 數值）、`alerts[0].fingerprint`（去重/關單對應）

### EL 完成 → T（排程串接）
```bash
# Airbyte sync 完成後（cron / n8n 觸發）
dbt deps && dbt build --target prod   # 依 lineage 依序 build + test
# Core v2.0 後可用 dbt State：只 build 有變更的 model（省 ~30% 成本）
```

## 4. 與「餐廳營運監控 / 數位資料倉庫」的關聯
- **ELT 分工落地**：POS 每日匯出 → Airbyte（Postgres source/destination + CDC 增量）→ raw 層 → dbt 轉 staging/marts → Grafana（即時單量、爐口利用率）＋ Superset（營運報表、趨勢）＋ n8n（SLA 違規自動通知/開單）
- **閉環實例**：爐口利用率 > 90% for 5m → Grafana webhook（HMAC 驗證）→ n8n → Telegram 值班通知 + 寫入 events 表 + AI Agent 查倉庫找可能原因 → HITL 審批 → 自動重跑 dbt 或通知店長
- **授權評估**：全內部使用 → 六支柱皆可免費自架；未來若對外提供「監控/資料服務」需先過授權決策樹（Airbyte managed service 是紅線）
- **生態訊號**：dbt 母公司與 Fivetran 合併後更強調「AI agent 的可信資料基礎」— 我們用 dbt 做 raw→marts 分層 + 測試/契約正是這個方向；**Agents Schema** 是未來可追蹤選項（把 marts 語意暴露給 AI 消費）
