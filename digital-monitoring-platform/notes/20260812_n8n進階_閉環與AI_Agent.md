# n8n 進階 — 閉環關鍵：AI Agent、Human-in-the-loop、與 Postgres 倉庫的整合

- 日期：2026-08-12（主題輪替 index=4 → n8n；8/4 已寫基礎篇，本篇為**進階深度篇**）
- 來源：n8n 官方文件（docs.n8n.io，`<頁面>.md` 後綴直接取 Markdown）+ npm registry / GitHub releases（版本驗證），2026-08-12 檢核
- 定位：n8n 是六支柱的「閉環關鍵」— 告警發生後「自動採取行動」；本篇聚焦 **AI Agent 節點進階用法、內建 HITL 審批、與 Postgres 數位倉庫的雙向整合**

## 1. 今日主題與概念摘要

1. **版本現況（2026-08-12 npm dist-tags 實測）**：`stable=2.33.7` / `latest=2.34.4`（GitHub release n8n@2.34.4，2026-08-07 發布）/ `beta=2.35.0`。**skill 內舊記錄 stable=2.33.5/beta=2.34.2 已過時，本次已更新**。
2. **Tools Agent 是唯一 agent 型別（v1.82+ 起）**：實作 LangChain tool calling 介面；特別的是它把 **output parser 當成「formatting tool」傳給模型**，因此能保證標準輸出格式。支援模型：OpenAI / Groq / Mistral / Anthropic / Azure OpenAI。關鍵參數：Prompt（預設吃前一節點 `chatInput`）、Max Iterations（預設 10）、System Message、Require Specific Output Format（Auto-fixing / Item List / Structured parser）、Enable Streaming（預設開，需 Chat Trigger 或 Webhook 的 Response Mode=Streaming）、Tracing Metadata（LangSmith）。
3. **⚠️ SQL Agent 已移除（2025-02）**：舊的「自然語言查資料庫」專用節點不存在了 — 現行做法是 **AI Agent + Postgres tool**（Postgres 節點標註「This node can be used as an AI tool」，參數可由 AI 自動填）。
4. **Human review for tool calls（內建 HITL，免自組 Wait 節點）**：AI Agent 的 Tools Panel 有 Human review 區塊，選審批頻道（Chat/Slack/Telegram/Discord/Teams/Gmail/WhatsApp/Google Chat/Outlook），把高風險 tool 接上去。agent 想用 gated tool → workflow 暫停 → 審批者看到「哪個 tool、什麼參數」（`$tool.name` / `$tool.parameters`）→ Approve 執行 / Deny 取消並告知 AI。子代理（agent 當 tool）中的 review 也正常運作。
5. **`$fromAI()` 動態參數**：`{{ $fromAI(key, description?, type?, defaultValue?) }}` — AI 依 context/其他 tool/輸入資料自己填 tool 參數（type=string/number/boolean/json）。⚠️ 僅限 AI Agent 的 tool 節點（Code tool 與非 tool 子節點不支援）。可嵌進一般 expression（如 `Generated by AI: {{ $fromAI("subject") }}`）。
6. **n8n Agents（新形態，一等公民 agent 工件）**：self-hosted 自 **v2.32.3（Beta）** 起可用。在 Agent Builder 建 **Model / Instructions / Tools / Skills（指令+工具捆綁）/ Channels（Slack/Telegram/Linear）/ Schedules（含 custom cron）/ Sub-agents（委派）/ Knowledge base / Memory（session 預設 + episodic）**；draft/published 快照版本管理；chat 內建工具審批。啟用：`N8N_ENABLED_MODULES=agents`（+`instance-ai` 得 AI Assistant 輔助建置）；⚠️ 不支援 queue mode、self-hosted Enterprise 尚未支援、一次 turn = 一次 execution。

## 2. 架構 / 流程說明

### 2.1 內建 HITL 審批流程（AI Agent 節點層級）
```
[AI Agent (Tools Agent)]
      │  Tools connector
      ├── tool A（免審批，如 Postgres Select 查 marts）
      └── tool B（gated，如 Postgres Update 改資料 / Slack 發訊息）
              │  agent 決定呼叫 tool B
              ▼
      workflow 暫停 → 審批請求（Slack/Telegram/Chat...）
              │  訊息含 $tool.name + $tool.parameters（AI 想做的事）
      ┌───────┴────────┐
    Approve          Deny
      │  tool B 以 AI 指定參數執行     │  動作取消，AI 被告知拒絕
      ▼                               ▼
   繼續 workflow                   AI 依 system prompt 應對（告知使用者/提替代方案）
```

### 2.2 事件驅動 ELT 閉環（Postgres Trigger 節點）
```
Airbyte(EL) → Postgres raw（新資料 insert）
                │  n8n Postgres Trigger（監聽 Insert，publish 時自動建 trigger+procedure）
                ▼
        n8n workflow 觸發 → 跑 dbt 重算 / 更新 marts 快取 / 通知下游
```
- 權限要求：n8n 憑證使用者需 TRIGGER privilege + schema CREATE privilege（可建專用 role，不一定要 superuser）
- 另一模式：`Listen to Channel`（pg_notify 風格）

### 2.3 完整閉環藍圖（Grafana 告警 → n8n → 倉庫 → 行動）
```
Grafana Alerting ──Webhook(HMAC 驗簽)──► n8n Webhook Trigger
        → IF 嚴重度分流
        ├─ 一般 → Postgres node（寫入事件日誌表）
        └─ 嚴重 → AI Agent（tools: Postgres 查 marts、Slack 通知、Call n8n Workflow 補救）
                    └─ gated tool（改資料/發外部訊息）→ Human review 審批 → 執行
```
- Postgres 節點防注入重點：Execute Query 用 `$1/$2` prepared statement + Query Parameters（n8n 自動 sanitize）；`$1:name` 可指定型別；Query Batching 選 Transaction 失敗自動 rollback；Insert 有 **Skip on Conflict**（≈ ON CONFLICT DO NOTHING）；`Output Large-Format Numbers As Text`（>16 位數避免精度錯）。
- **Postgres Chat Memory**：AI Agent 對話記憶可直接存自家倉庫 Postgres（另有 Simple Memory / Redis / Motorhead / Xata / Zep，進階用 Chat Memory Manager）—「記憶也進倉庫」完全貼合單一真相源。

## 3. 實用指令 / 設定

### 3.1 啟用 Agents 與 AI Assistant（self-hosted，接本棧 compose 的 n8n 服務）
```yaml
# docker-compose.yml 的 n8n service 增加：
environment:
  N8N_ENABLED_MODULES: "instance-ai,agents"      # agents=agent 工件；instance-ai=AI Assistant 輔助建置
  N8N_INSTANCE_AI_MODEL: "anthropic/claude-opus-4-8"   # 預設即此值；openai/gpt-5.5、openrouter/deepseek/deepseek-v4-pro 亦可
  N8N_INSTANCE_AI_MODEL_API_KEY: "sk-ant-xxx"
  N8N_INSTANCE_AI_SANDBOX_ENABLED: "true"
  N8N_INSTANCE_AI_SANDBOX_PROVIDER: "daytona"    # 生產建議；本機開發可用 n8n-sandbox
  # 本地模型（OpenAI-compatible）：
  # N8N_INSTANCE_AI_MODEL_URL: "http://localhost:1234/v1"
  # channels（Slack/Telegram/Linear 連 agent）需公開網址：
  # WEBHOOK_URL: "https://your-public-url"
```
- ⚠️ 2026-08-12 現況：agents 支援 regular mode，**queue mode 不支援**；knowledge base 需 Daytona sandbox（preview）。

## 4. 與「餐廳營運監控」及「數位資料倉庫」的關聯

- **告警閉環**：Grafana 告警 Webhook（HMAC 驗簽，見 skill 檢核的 4 步驗簽法）→ n8n Webhook Trigger → AI Agent 用 Postgres tool 查 marts 層（fact_ros_scenario_metrics / SLA 排名視圖）理解異常 → 值班通知；「重算 dbt / 修資料」這類動作掛 **Human review**，避免 AI 誤動作。
- **事件驅動 ELT**：Postgres Trigger 監聽 raw 層新資料 → 自動觸發 dbt 重跑/儀表板資料更新 — 把「排程輪詢」升級為「變更即處理」。
- **AI 值班助理**：n8n Agents 的 Schedules（custom cron）可讓 agent 每天自動巡倉庫指標；Skills 把「SLA 違規分析」打包成可重用行為；審批在 chat/Slack 內完成。
- **記憶入倉**：Postgres Chat Memory 讓 agent 跨次對話脈絡存進 restaurant_warehouse，符合「單一真相源」。
- **安全預設**：Postgres node 一律用 query parameters 防 SQL injection — 尤其是 AI 生成 SQL 的場景。
