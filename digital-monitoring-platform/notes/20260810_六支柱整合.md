## 1. 今日主題與概念摘要

1. **生態訊號：ELT 管線全面 AI-ready**。Fivetran + dbt Labs 合併後的首波聯合產品（2026-06-01）已全數就位：**dbt Core v2.0 alpha**（Rust Fusion engine 開源為 Apache-2.0，parse 快 10x，新增 SQL comprehension / column-level lineage / 即時 SQL 回饋）、**dbt State preview**（依 warehouse metadata + model SQL 判斷變更，build/skip/clone/defer，平均省 >30% compute）、**dbt Wizard**（原生 dbt 知識的 agent，ADE-bench 76%）、**Fivetran AI Connector Agent beta**（爬 API 文件自動生成 connector）、**Agents Schema**（倉庫單一 schema 存 metric/語意模型/lineage/文件，純 SQL 表，作為 AI agent 共享 context）。
2. **dbt 2026-05 shipped 續報**：**dbt Developer Agent（Preview）**（理解 lineage，跨 SQL/YAML/tests/docs 一次改完）、**dbt Agent Skills（GA）**（github.com/dbt-labs/dbt-agent-skills — 教通用 coding agent 寫 dbt 的結構化知識）、**dbt MCP Server OAuth（Beta）**（Claude/ChatGPT/Glean 用既有 dbt 登入）、**DuckDB adapter（Beta）**（無 warehouse 本地跑 dbt — 學習/CI 神器）。
3. **閉環接口實作細節（Grafana → n8n）**：webhook 預設 payload 完整欄位（receiver/status/orgId/alerts[]/groupLabels/commonLabels/externalURL/version/groupKey/truncatedAlerts/title/state/message；alerts[] 含 labels/annotations/values/fingerprint/startsAt/endsAt/generatorURL/silenceURL/dashboardURL/panelURL）；HMAC-SHA256 簽章 `HMAC(timestamp + ":" + body)` hex 輸出，可配 timestamp header 防 replay；**接收端驗簽 4 步**。
4. **T 層落地（今日實作）**：建立 `scripts/dbt_project/` 完整 dbt 專案骨架 — staging 3 models 從 raw JSONB 拆解（`->>` 型別化 / `jsonb_each` / `jsonb_to_recordset`）+ marts 3 models（星形事實表 / FILTER 樞軸 / SLA 排名）+ sources.yml（freshness）+ schema.yml（資料品質契約），並以 PGlite 實測驗證。
5. **實測抓到 2 個真實 bug（誠實原則的價值）**：① PG18 的 `jsonb_each` 是 **OUT 參數函數**，寫 `AS st(station_type TEXT, ...)` 欄位清單會報 redundant — 欄位固定 key/value，須在 SELECT 層改名；② raw JSON `violation_details[]` 欄位名是 `sla`/`actual`（以 ros_import.py 讀取為準），不是 `sla_seconds`/`actual_seconds`。
6. **PG18 語法對照**：`jsonb_each`（物件→列，OUT 參數，**不可**帶欄位清單）vs `jsonb_to_recordset`（陣列→列，**必須**帶欄位清單）— 兩者都要配 `CROSS JOIN LATERAL`。

## 2. 架構 / 流程說明

### 六支柱整合藍圖（AI-ready 版）
```
外部資料（POS/ROS/ERP/API）
   ↓ ① Airbyte（EL：550+ connectors、CDC 增量；或 Fivetran AI Connector Agent 自動生成）
┌──────────────────────────────────────────┐
│ PostgreSQL 數位資料倉庫（單一真相源）       │
│  ├─ raw     （EL 原封不動寫入）            │
│  │    ↓ ② dbt（T：本機 dbt_project/ 已落地）│
│  ├─ staging （jsonb_each/->> 拆解清洗）    │
│  ├─ marts   （星形事實表/樞軸/排名）        │
│  └─ AGENTS  （Agents Schema：metric/lineage │
│              定義供 AI agent 讀取）【未來】  │
└──────────────┬───────────────────────────┘
      ┌────────┼───────────┐
 Grafana 秒級+告警│ Superset BI│ n8n 自動化
      │           │ 分析報表   │ 通知/開單/補救
      └─Webhook(HMAC)─► n8n 閉環
```

### 告警閉環驗簽流程（Grafana → n8n，2026-08 docs 檢核）
```
[Alert Rule] 爐口利用率 > 90% for 5m
   ↓ firing
[Notification Policy] label 路由 → Contact point (Webhook, HMAC secret)
   ↓ POST JSON（status/labels/values/fingerprint）
   ↓ header: X-Grafana-Alerting-Signature = HMAC(timestamp + ":" + body) hex
[n8n Webhook Trigger]
   ① 取 header 簽章
   ② 驗 timestamp header 新近性（防 replay）
   ③ 用共享 secret 重算 HMAC-SHA256
   ④ 比對 → 通過才處理
   ├─ status == firing  → 嚴重度分支（通知/開單/AI 分析 + HITL 審批）
   └─ status == resolved → 關單（用 fingerprint 對應）
```

### dbt 專案骨架（本機 T 層，今日落地）
```
scripts/dbt_project/
├── dbt_project.yml    staging=view / marts=table
├── profiles.yml       連線範例（warehouse/restaurant_warehouse）
└── models/
    ├── sources.yml    raw source + freshness + source tests
    ├── schema.yml     not_null/unique/accepted_values（資料品質契約）
    ├── staging/       stg_ros_sim_summary / stg_ros_sim_station_util / stg_ros_sim_sla_violation
    └── marts/         fact_ros_scenario_metrics / v_ros_station_util_pivot / v_ros_sla_ranking
```

## 3. 實用指令

### dbt 專案（T 層）執行
```bash
# 先有 raw 資料（EL：ros_import.py 或 Airbyte）
python scripts/ros_import.py --reports "<ROS>/simulator/reports"

# T：連線設定 + build + test + 文件
cp scripts/dbt_project/profiles.yml ~/.dbt/profiles.yml   # 編輯密碼
dbt deps && dbt run --target dev && dbt test --target dev
dbt docs generate && dbt docs serve   # lineage/文件網站 :8080
```

### 驗證（無 Docker 亦可）
```bash
# dbt 模型 SQL 用 PGlite 實測（raw JSONB → staging → marts 全鏈）
npm i @electric-sql/pglite && node verify_dbt_staging.mjs scripts/dbt_project/models
bash scripts/run_tests.sh   # 統一 5 項驗證入口
```

### Grafana webhook → n8n（閉環）
1. Grafana：Alerting → Contact points → Webhook，URL=`http://n8n:5678/webhook/grafana-alert`
2. 開啟 HMAC Signature（Secret + 可選 Timestamp Header）
3. n8n：Webhook Trigger → Code node 驗簽 4 步（見上圖）→ IF status 分支
4. 關單對應用 `alerts[].fingerprint`；`values` 是 condition 數值；`truncatedAlerts` 表示超出 Max Alerts 被截斷

## 4. 與「餐廳營運監控 / 數位資料倉庫」的關聯
- **T 層正式落地**：之前 warehouse_schema.sql 是手工 DDL；今天 dbt_project/ 讓 raw→staging→marts 有了可版控、可測試、有 lineage 的正式版本 — 與 EL（ros_import/Airbyte）構成完整 ELT 管線
- **資料品質契約**：schema.yml 的 accepted_values 鎖死 8 種爐口型別、not_null 鎖死關鍵指標 — 消費層（Grafana/Superset）可安心直查 marts
- **閉環**：SLA 違規告警 → Grafana webhook（HMAC 驗簽）→ n8n 通知值班/開單/觸發 dbt 重跑 — 從「被動看板」到「主動運營」
- **未來追蹤**：Agents Schema（AGENTS schema）可把 marts 的 metric/lineage 暴露給 AI agent；DuckDB adapter 可在無 Docker 環境本地跑 dbt 練習
