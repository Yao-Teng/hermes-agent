# Grafana 13 新世代儀表板：Dynamic Dashboards + Git Sync + 變數進化

- 日期：2026-08-09（主題輪替 index=1 → Grafana；繼 08-05 基礎概念後，今日深挖 **Grafana 13 新世代功能**）
- 來源：grafana.com/docs（release-13.1.3）+ grafana.com/whats-new 官方公告，2026-08-09 檢核
- 定位：Grafana 13 是「儀表板即程式碼（GitOps）」與「動態儀表板」成熟的世代 — 直接影響本平台建置層的儀表板策略

---

## 1. 今日主題與概念摘要

1. **Dynamic Dashboards 正式 GA（v13.0，2026-04-08 公告）**
   - 歷程：Experimental（2025-04-10）→ Public preview（2026-01-14）→ **GA（2026-04-08）**，Cloud 與 self-managed 全部**預設啟用**，既有儀表板開啟時自動遷移新 schema，無需手動步驟
   - **Tabs 成為一等公民**：與 rows 並列的水平分組；**可巢狀三層**（tabs 內放 rows、rows 內放 tabs）
   - 兩種版面模式（建立時選，之後可改）：**Auto grid**（設定最小欄寬/列高/最大欄數，面板自動重排適應螢幕）vs **Custom layout**（手動拖曳精準定位）
   - **Show/Hide Rules（動態內容）**：依「變數值」或「查詢結果」顯示/隱藏面板、rows、tabs — 例如 `$datasource` 是 Prometheus 才顯示 K8s 區塊；查詢無資料自動隱藏空 row。**不用再維護多份近似儀表板**
   - 側邊欄編輯：Add element（面板/分組/儀表板控制）、Content outline（樹狀結構快速跳轉）、Edit as code（直接編輯 JSON）
2. **Git Sync GA（雙向 GitOps，dashboards as code 正式化）**
   - v13.0 GA：連 GitHub/GitLab/Bitbucket/任何 git repo，**在 Grafana UI 內直接編輯→儲存→commit→開 PR**，不用離開 UI
   - v13.1 強化（全 GA）：**UI 匯入儀表板 JSON 到 Git Sync 資料夾**（可選檔案路徑/branch/commit message/workflow）、**root-level 同步**（repo 同步到 Grafana 實例頂層，不需父資料夾）、**Verified commits**（GPG/SSH/S/MIME 簽章，git provider 顯示 Verified，滿足簽章與 branch protection 稽核要求）；Public preview：資料夾內 README.md 直接內嵌顯示（放 runbook/ownership 說明）
   - 官方文件路徑已改為 `docs/grafana/latest/as-code/observability-as-code/git-sync/`
3. **變數進化（模板變數不是只能下拉了）**
   - **Multi-property variables GA**（OSS/Enterprise，先前僅 Cloud）：一個變數對應多個值
   - **Section-level variables GA**：變數可作用在**單一 row/tab 層級**，切 `$instance` 不會一次影響所有面板 — 解決「不同服務被迫拆多個儀表板」的老問題（餐廳多店/多爐口儀表板直接受惠）
   - **Quick filters & data grouping GA**：新「Filter and Group by」儀表板控制，內建預設過濾器、過濾歷史、統一 filters overview、panel 級 drilldown — 部分取代 ad hoc filters 的苦工
   - 2026-07-13：query variables 編輯器改版（建立變數更容易）
4. **其他 GA 亮點**：Time series → table transformation（加 `trend` 欄位，sparkline cell 型別做緊湊總覽）、Annotations clustering（大量註記叢集化）、Copy & paste panel styles（同型面板一鍵複製樣式）、Series visibility filter（圖例直接過濾顯示系列，不動 query）、新 Gauge 視覺化、Legend limits（數百 series 不爆 DOM）、Restore deleted dashboards（免支援單自行還原）
5. **Grafana Assistant（AI，Public preview）**：v13.1 起 **Enterprise 預裝**（免裝 plugin，連 Grafana Cloud 帳號即可用）；自然語言 onboarding/探索/建儀表板；**新增 8 個可查資料源**：Snowflake、MongoDB、Oracle、Elasticsearch、Dynatrace、Honeycomb、Zabbix、Jira（單一對話跨系統調查）。OSS 目前無 Assistant（誠實標註：本平台 OSS 部署不適用，AI 建板靠「儀表板 JSON 版控 + 模板」）
6. **Dashboard schema v2 + provisioning 相容**：動態儀表板用**新 schema v2**；以 API/Terraform/Git Sync/provisioning 餵入的 **v1 dashboard JSON 照常運作**（載入時自動遷移 v2）— **既有 provisioning 資產零破壞**，本平台可直接沿用 08-05 的 provisioning 策略

## 2. 架構 / 流程說明

### Dynamic Dashboards 結構（v2 schema）
```
Dashboard（auto grid 或 custom layout）
 ├─ Tabs（水平分組，一級）＋ Rows（垂直分組）→ 可巢狀三層
 │    └─ Section-level variables：$store 只作用在「爐口區」tab
 ├─ Panels：query + visualization + Panel styles（一鍵套用配色/門檻）
 ├─ Dashboard controls：變數 / annotations / dashboard links / filters
 │    └─ Quick filters：Filter and Group by（含歷史與 drilldown）
 └─ Show/Hide rules：依變數值或查詢結果 顯示/隱藏 面板或區塊
```

### Git Sync 雙向 GitOps 流程（儀表板即程式碼）
```
Git repo（dashboards/*.json 版控，與 dbt models、warehouse_schema.sql 同 repo）
        ↓ Git Sync（GA，雙向）
Grafana 實例
  ├─ 雲端改：UI 編輯 → Save & commit → PR（Verified commits 簽章）
  └─ repo 改：push → 同步進 Grafana（root-level 或指定 folder）
        ↓
Provisioning（v1 JSON 自動遷移 v2；schema v2 亦可直接寫）
```

### 與「餐廳營運監控」的落地對照（本平台 marts 層為資料源）
```
PostgreSQL marts（fact_ros_scenario_metrics / v_ros_station_util_pivot / v_ros_sla_ranking）
        ↓ postgres datasource（read-only 角色）
Grafana 13「餐廳營運總覽」
 ├─ Tab「營運績效」：SLA 達成率 stat、各場景 completion bar gauge、SLA 排名 table
 ├─ Tab「爐口利用」：v_ros_station_util_pivot table（wok/grill/fry/steam/cold/oven/bar/pack 八爐口）
 ├─ Section-level 變數 $scenario：只影響單一 tab，切場景不干擾其他面板
 └─ Show/Hide rule：無 SLA 違規資料時自動隱藏「違規」row
 ⏭ 秒級時間序列待 metrics 層（TimescaleDB hypertable）建好後接 time series 面板 + alerting
```
> 誠實註記：目前 marts 是聚合表（無時間欄位），故今日範例儀表板用 table/stat/bar gauge 型查詢；真正的 time series 面板與告警需 metrics 層（TimescaleDB）就緒，那是 PostgreSQL 日（08-08）已規劃的方向。

## 3. 實用指令與設定

```bash
# Docker 一鍵起（同 08-05；Grafana 13 預設即 dynamic dashboards）
docker run -d --name=grafana -p 3000:3000 grafana/grafana

# 本平台 compose（scripts/docker-compose.yml）：grafana 服務已掛載 provisioning
#   ./grafana/provisioning → /etc/grafana/provisioning（datasources/ + dashboards/）
#   ./grafana/dashboards    → /var/lib/grafana/dashboards（dashboard JSON 放這裡）
docker compose up -d grafana
```

Git Sync 設定入口（v13.1，UI 操作）：Administration → Git Sync → 連 repo → 選資料夾/root-level → 設簽章 key（GPG/SSH/S/MIME）→ 之後 UI 編輯即 commit + PR。

今日產物（scripts/grafana/，對齊 compose 掛載點）：
- `provisioning/datasources/postgres-warehouse.yml`：Postgres 倉庫資料源（read-only 建議角色 grafana_ro）
- `provisioning/dashboards/restaurant-ops.yml`：dashboard provider（指到 /var/lib/grafana/dashboards）
- `dashboards/restaurant-ops-overview.json`：餐廳營運總覽 v1 schema 起手式（載入自動遷移 v2），含 `$scenario` 變數 + stat/bar gauge/table 面板

## 4. 與「數位資料倉庫」的關聯
- **儀表板即程式碼成熟**：Git Sync GA 後，「倉庫 schema（SQL）+ 轉換（dbt models）+ 儀表板（JSON）」三者可完全放同一 repo 版控 — 全平台可重現、可稽核（Verified commits）
- **Dynamic dashboards 減少重複**：多店/多爐口不用拆儀表板 — section-level variables + show/hide rules 一個儀表板搞定，變數維護成本下降
- **v1 → v2 無痛**：既有 provisioning JSON 資產（08-05 規劃）零破壞，建置層可先寫 v1 起手式
- **AI 助理（Enterprise）不適用 OSS**：本平台走 OSS 部署，建板策略 = 模板 + JSON 版控，不依賴 Assistant
